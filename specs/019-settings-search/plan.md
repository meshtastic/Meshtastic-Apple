# Implementation Plan: Settings Search

**Branch**: `019-settings-search` | **Date**: 2026-09-13 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `/specs/019-settings-search/spec.md`

## Summary

Add a search field to Settings that finds an individual control by name, keyword or option
value, shows which screen and section it lives on, and opens that screen when tapped. The
in-app documentation is searched from the same field and returned in its own section.

The design splits the index in two. Language — labels, descriptions, keywords — lives in
app-side Swift declared with `String(localized:)` so it reaches the string catalog.
Structure — which fields exist, their bounds and units, and whether they are DIY-only,
admin-only or deprecated — comes from the generated field-metadata registry. The two join
on proto message name and tag.

This is a change from what the spec assumed. The spec expected user-facing strings to ride
along in `(meshtastic.field_metadata)`; research found the Swift generator emits plain
string literals that Xcode's extractor cannot see, which would have made every indexed
label permanently English. Moving language app-side also drops the upstream dependency
from "a second protobufs PR annotating all 221 fields" to "whatever #952 lands with", so
the feature no longer sits behind a protobuf release. See [research.md](./research.md) D1.

The drift guard is what makes a curated index maintainable: a test parses the config
protos and fails when a field is neither indexed nor exempted, alongside a test that every
entry's label still exists in the view file it claims to live in.

## Technical Context

**Language/Version**: Swift (latest stable), Swift Concurrency
**Primary Dependencies**: SwiftUI (`.searchable`, `NavigationStack`), Foundation (`localizedStandardContains`), `MeshtasticProtobufs` (generated `FieldMetadataRegistry`), the bundled docs index
**Storage**: None — the index is static, built once at launch and held in memory; no SwiftData schema changes
**Testing**: Swift Testing (`@Suite`, `@Test`, `#expect`) — index completeness against the config protos, label drift against view sources, per-screen entry counts, ranking determinism
**Target Platform**: iOS 17+, iPadOS 17+, macOS 14+ (Catalyst)
**Project Type**: Mobile app — feature addition to the existing Settings screen
**Performance Goals**: Filtering the full index per keystroke with no visible lag; index construction off the first frame
**Constraints**: Works offline and with no radio connected; no new third-party dependency; must build and search correctly when the field-metadata registry is absent
**Scale/Scope**: ~270 indexed controls across 42 settings destinations, 221 config proto fields in 29 messages, 31 documentation pages

**Structure Decision**: The index is app data, not view code, so it sits under
`Meshtastic/Model/` beside `ConfigModels.swift` — the SwiftData mirror of the same protos.
Both `Model/` and `Views/` are synced folders in `project.yml`, so new files need no
project regeneration and `xcodegen-drift.yml` stays green. The generated registry stays in
the protobuf package for the reasons in research D2; pointing `--fieldmeta-swift_out` at
`Sources/meshtastic` rather than `Sources` matters, because this plugin emits a bare
filename and a loose file under `Sources/` breaks the package's implicit target path.

## Sequencing

Three changes, each its own pull request, per the repo's one-change-per-PR rule:

1. **String catalog migration (FR-016)** — `.localized` → `String(localized:)` across 321
   sites in `Meshtastic/Enums/`, plus `UpdateIntervalPicker.pickerLabel` becoming
   `LocalizedStringKey`. Independently valuable: 239 strings are untranslated today
   regardless of search. Must land first, because search indexes those strings.
2. **Settings search** — the index, the engine, the UI and the drift tests.
3. **Field-metadata wiring** — the `gen_protos.sh` phase, the submodule bump and the CI
   checkout fix, once #952 merges. Search works without it and gains the DIY-only,
   admin-only and deprecated filtering when it lands.
